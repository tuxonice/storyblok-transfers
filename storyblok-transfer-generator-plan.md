# Storyblok Transfer Generator — Package Plan

## Overview

A framework-agnostic PHP package that fetches component schemas from the Storyblok Management API and generates PHP Transfer Object classes using `tuxonice/transfer-objects`.

```
Storyblok Management API → JSON definition files → PHP Transfer classes
```

---

## Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Framework | Agnostic | Usable in Laravel, Symfony, or plain PHP |
| `bloks` field | `BlokTransfer[]` (Option A) | Simple, no polymorphic complexity |
| Relation fields (`story`) | Always `string` | UUID only — resolution handled by the consumer |
| Nullable fields | All nullable by default | Storyblok fields are rarely guaranteed |

## Components

### `StoryblokManagementClient`
- Wraps Guzzle HTTP client
- Authenticates with `Authorization: Bearer {token}`
- Exposes `getComponents(string $spaceId): array`
- Endpoint: `GET https://mapi.storyblok.com/v1/spaces/{id}/components/`

### `ComponentSchemaFetcher`
- Calls `StoryblokManagementClient::getComponents()`
- Returns normalized array of components with their schema fields

### `FieldTypeMapper`
- Maps Storyblok field types to DTO definition types
- See field type mapping table below

### `DefinitionFileWriter`
- Converts a component name + mapped properties into a JSON definition file
- Converts component names to `PascalCase`
- Writes to the configured `definitionsPath`

### `StoryblokTransferGenerator`
- Orchestrates all of the above
- Ensures output directories exist
- Calls `DataTransferBuilder->build()` after writing definition files

## Generated Output Example

For a `product_core` component in Storyblok, the generator produces:

### `storyblok/definitions/ProductCore.json`
Intermediate file — version-controllable, human-readable.

```json
{
    "transfers": [
        {
            "name": "ProductCore",
            "properties": [
                { "name": "code", "type": "string", "nullable": true },
                { "name": "productName", "type": "string", "nullable": true },
                { "name": "productSlug", "type": "string", "nullable": true },
                { "name": "image", "type": "AssetTransfer", "nullable": true },
                { "name": "relatedProduct", "type": "string", "nullable": true },
                { "name": "categoryIds", "type": "string[]", "singular": "categoryId" }
            ]
        }
    ]
}
```

### `src/DataTransferObjects/ProductCoreTransfer.php`
Auto-generated by `tuxonice/transfer-objects` — never edited manually.

## Build Steps

Recommended implementation order:

1. **`StoryblokManagementClient`** — get the real API response in hand; inspect actual field shapes
2. **`FieldTypeMapper`** — iterate against real component schemas from the space
3. **`DefinitionFileWriter`** — straightforward serialisation step
4. **`StoryblokTransferGenerator`** — wire everything together
5. **`bin/generate`** — standalone CLI script for framework-free usage

---

## `bin/generate` — Standalone CLI Script

Usable without any framework:

```php
#!/usr/bin/env php
<?php

require __DIR__ . '/../vendor/autoload.php';

$spaceId         = $argv[1] ?? null;
$token           = $argv[2] ?? null;
$definitionsPath = $argv[3] ?? __DIR__ . '/../storyblok/definitions/';
$outputPath      = $argv[4] ?? __DIR__ . '/../src/DataTransferObjects/';
$namespace       = $argv[5] ?? 'App\\DataTransferObjects';

if (!$spaceId || !$token) {
    echo "Usage: bin/generate <space-id> <token> [definitions-path] [output-path] [namespace]\n";
    exit(1);
}

$generator = new StoryblokTransferGenerator(
    spaceId: $spaceId,
    token: $token,
    definitionsPath: $definitionsPath,
    outputPath: $outputPath,
    namespace: $namespace,
);

$generator->generate();

echo "Done.\n";
```

| `copyright` | `?string` |

### `LinkTransfer`
| Property | Type |
|---|---|
| `id` | `?string` |
| `url` | `?string` |
| `linktype` | `string` |
| `fieldtype` | `string` |
| `cached_url` | `?string` |

### `BlokTransfer`
| Property | Type |
|---|---|
| `component` | `string` |

Minimal — just enough to type the polymorphic `bloks` array. The consumer is responsible for further discrimination if needed.

## Out of Scope (for now)

- Framework-specific command wrappers (Laravel Artisan, Symfony Console)
- Resolved relation variants (relation fields are always `string`)
- Custom plugin field introspection
- `BlokTransfer` factory / discriminated union (Option B)
- Storyblok webhook integration for auto-regeneration on schema change
