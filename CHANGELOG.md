# Changelog

All notable changes to this package are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
the package uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [0.4.0] - 2026-11-10

The cache can now be cleared on demand, so a change published in Storyblok
shows up at once instead of within 5 minutes. Nothing changes unless you call it.

### Added

- **Clearing the cache.** `StoryblokContent::clearCache()` empties the cache so
  the next read asks Storyblok, for example from a Storyblok webhook when
  content is published. `CachingContentClient::clear()` does the same for a
  client built by hand. See
  [Clearing the cache](documentation/caching.md#clearing-the-cache).

## [0.3.0] - 2026-11-10

Published content can now be cached in any PSR-16 cache, with the last copy
served while Storyblok is unavailable. Nothing changes unless you pass a cache.

### Added

- **A built-in cache.** Pass any PSR-16 cache to `StoryblokContent::create()` or
  `fromEnvironment()`, and published reads are cached for 5 minutes. If
  Storyblok fails, the last copy is served for up to a day instead of an error.
  Drafts are never cached. `CachingContentClient` takes custom timings, a key
  prefix and a PSR-3 logger. See [Caching](documentation/caching.md).
- New dependencies: the interface packages `psr/simple-cache`, `psr/clock` and
  `psr/log`.

## [0.2.0] - 2026-11-10

Rich text fields now hydrate into a `RichtextTransfer`, including the
components inserted into them. This is a breaking change for generated code;
read *Changed* before regenerating.

### Changed

- **Breaking: `richtext` fields are now `?RichtextTransfer`, not `?array`.**
  Updating the package alone changes nothing: classes generated by 0.1.0 keep
  their `?array` rich text properties and still hydrate as before. The change
  arrives when you regenerate. After that, a rich text getter returns a
  `RichtextTransfer` instead of Storyblok's raw array:
  - where you passed the array to a renderer, pass `$field->toDocument()`, the
    same document in the shape renderers expect
  - where you read `$field['content']`, use `$field->getContent()`

  See [Rich text](documentation/rich-text.md).

### Added

- **Components inside rich text are hydrated.** Components an editor inserts into
  rich text become your generated classes, available through
  `RichtextTransfer::getBloks()` by blok id, so a renderer can draw them.

## [0.1.0] - 2026-11-09

The first release.

### Added

- **Generating transfers.** `StoryblokTransferGenerator` and `vendor/bin/generate`
  read a space's component schemas from the Management API and write one JSON
  definition and one PHP transfer class per component. Fields that cannot be
  generated are left out and reported as warnings.
- **Bundled transfers** for asset, link and blok fields: `AssetTransfer`,
  `LinkTransfer` and `BlokTransfer`.
- **Hydration.** `StoryblokHydrator` turns a Storyblok content array into the
  generated classes, including nested bloks at any depth. A blok whose component
  has no generated class stays a raw array instead of throwing.
- **Reading content.** `StoryblokContent` reads stories from the Content
  Delivery API into the generated classes:
  - stories by slug or uuid, and listings through `StoryQuery`, with filters,
    sorting and pagination
  - drafts, languages and cache versions through `ContentOptions`
  - resolved relations as whole related stories through `getRelation()`,
    including relations past Storyblok's 50-per-response limit
  - the links tree and datasource entries, with every page of entries fetched
  - a `ContentClient` interface to wrap for caching
- **Regions.** Both generating and reading work with spaces in any Storyblok
  region, through `STORYBLOK_MANAGEMENT_BASE_URI` and
  `STORYBLOK_CONTENT_BASE_URI`.
- **Documentation** in `documentation/`, starting with a getting-started guide.
- Works with **Guzzle 7 or 8**.

### Notes

- Requires **PHP 8.3** or newer.
- `RichtextTransfer` ships with the package but is not yet used by the generator
  or the hydrator; rich text fields still arrive as arrays.
